### How I work with AI

My day-to-day AI-assisted development follows the methodologies of the [Gentleman Programming](https://github.com/Gentleman-Programming) ecosystem, mainly through [Gentle Shell](https://github.com/Gentleman-Programming/gentle-shell) on Pi.

| Practice | What it means in my workflow |
| :--- | :--- |
| **ODD** · Organic Driven Development | Explore read-only first, keep small changes lightweight, and keep substantial work recoverable. |
| **SDD** · Spec-Driven Development | A methodology I apply to larger changes: explore → propose → spec → design → tasks → apply → verify → archive, with OpenSpec-style artifacts. |
| **Strict TDD** | When enabled: RED → GREEN → REFACTOR, with observable test evidence. |
| **RDD** · Receipt-Driven Development | Risk-scoped review of a frozen candidate; delivery remains a human decision. |
| **Adversarial review** | Independent review lenses (risk, readability, reliability, resilience) and blind dual review for high-stakes changes. |
| **Reviewable delivery** | Work-unit commits, chained PRs, and issue-first pull requests that keep reviewer load small. |

**Concepts and integrations I use:** subagent orchestration with bounded roles · reusable agent skills · persistent memory with [Engram](https://github.com/Gentleman-Programming/engram) · MCP · Context7 · CodeGraph · model routing by task.
